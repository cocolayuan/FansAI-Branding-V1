# Chart：形式服务于数据关系

本文件记录 FansAI Branding Data 当前已采用的图表决策与延伸规则。
沿用 Growth 的视觉秩序，在数据语义允许的范围内变化形式；不要把所有指标做成同一种仪表盘。
文中的数量、比例和人员均是示例，不是组件常量，也不是新数据的默认值。

## 1. 审美决策

- 先明确用户要比较什么，再选形状、颜色与动效；形式必须能解释数据关系。
- 黑色页面底，黑青/灰青卡面，薄荷与冰蓝为主；有意义的阶段或风险可使用钴蓝、琥珀。
- 大数字采用轻字重和稳定的等宽数字，标题、读数、说明、图形有明确层级。
- 创意来自比例块、单位阵列、纹理、局部光感和交互反馈，不来自无语义的复杂造型。
- 深色适合密集列表与 KPI；白色分析卡可作有限的节奏变化，不将整个数据列表铺白。
- 用留白、面色和圆角分组，不补装饰性细分隔线、刻度网或发光边框。
- 保留真实曲线和有用的回本基准；“少线”不等于删除理解数据所需的信息。
- 图表不应依靠动画才能读懂；静态状态本身必须完整。

## 2. 按数据关系选型

| 用户问题 / 数据关系 | 当前采用或优先选择 | 必须说明 |
| --- | --- | --- |
| 有多少客户 / 记录 | 单位点阵、短划线、计数柱 | 每个亮标记代表多少记录，聚合倍率 |
| 已收与待收各占多少 | 并排比例块，轻厚度与不同纹理 | 两者合计为分母，块宽对应占比 |
| 客户合同是否集中 | 100 点占比矩阵＋分组明细 | 每点约 1%，精确金额与占比另列 |
| 在制项目分布在哪些阶段 | 横向阶段比例块＋图例 | 阶段数量、合计、零阶段处理 |
| 建联后如何转化 | 同尺度阶段数量柱＋上一步转化率 | 归属周期、阶段顺序、转化分母 |
| 谁贡献更多 | 排序横条 / 排名条 | 排序指标、比较基准与精确读数 |
| 历史如何变化 | 真实时间序列曲线 | 日期、单位、缺失点与当前选中值 |
| 是否回本 | Growth 的重点 ROI 仪表盘＋历史曲线 | ROI＝收入÷总成本，100%为回本 |
| 距离真实目标多远 | 目标进度条＋实际/目标读数 | 目标来源；未设目标不显示伪完成率 |
| 正负盈亏如何比较 | 共享零点的发散条 | 左亏右盈、同组统一尺度、正负金额 |

计数、构成、趋势、排名和目标进度不能相互冒充。
单个累计数值没有时间序列时，不为它编造折线或随机柱高。

## 3. 六张 Global KPI 的微图形

实现：`mobile/customers-src/kpi-cards.jsx` 与 `mobile/customers-src/kpi-cards.css`。
两组各三列；每卡依次为标签、读数、上下文说明、底部微图形。

| 指标 | 组件 / 形式 | 数据与配色 |
| --- | --- | --- |
| 客户数 | `CXKpiMatrix`，14×9＝126 槽 | 总客户计数；薄荷 |
| 新增客户 | `CXKpiMatrix`，7×10＝70 槽短划线 | 选定周期新建档计数；冰蓝；可切换新增筛选 |
| 已签约客户 | `CXKpiCountBars`，短计数柱 | 选定周期签约客户计数；冰蓝/薄荷配合 |
| 在制项目 | `CXKpiStages`，横向比例块 | 立项、合同、制作、验收的实际记录数 |
| 本周交付 | `CXKpiCountBars` 的 `stems` | 实际本周交付计数；冰蓝细杆与端点 |
| 已延期 | `CXKpiCountBars` 的 `hatched` | 实际延期计数；有延期时用琥珀斜纹 |

112 / 66 / 4、25 / 2 / 6、15:5:5 都是当前演示数据的结果，不得硬编码为视觉模板。
总客户来自 summary；新增和签约按已有记录与周期计算；项目指标来自已有项目状态和日期。
沿用宿主数据范围，不把当前加载记录的计数自动宣传为后端全量统计。

### 计数单位与聚合

- `cxKpiCount` 仅接收可转换为非负安全整数的值；空值、布尔值、空字符串、负数和小数不可用。
- `cxKpiUnits(value, capacity)` 在数值不超过容量时使用单位 1。
- 超过容量时，单位为 `10 ^ ceil(log10(value / capacity))`。
- 完整亮格数为 `floor(value / unit)`，末格比例为 `(value % unit) / unit`。
- 末格保留真实余数，不向上画成一整格，不丢掉超容量的记录。
- 聚合时显示 `×unit`；可访问说明同时读出总数、每格单位和末格余数。
- 例如总客户 137、容量 126：单位为 10，显示 13 整格和 0.7 格，并标 `×10`。
- 三种计数柱共用容量 12；柱数表达计数，柱高只在末根表达不足一单位的余数。
- 计数柱没有时间轴，不将等高柱解读为趋势。
- 数字达到 1 万时可使用紧凑读数；完整精确值保留于 `title` 和 `aria-label`。

### 项目阶段构成

- `CXKpiStages` 的四阶段计数必须全部有效，且合计等于 `activeCount`，才显示比例图。
- 块宽按真实计数 `flexGrow` 分配；固定块间隙用于区分阶段，不表示数量。
- 比例块、紧邻图例及可访问说明仅列出大于零的阶段，保留名称与精确数量；零阶段不画虚构宽度。完整四阶段输入仍参与合计校验。
- 合计为零显示“暂无”；计数缺失或合计不一致显示“—”，不补齐或伪造分布。
- 当前阶段配色依次为薄荷、冰蓝、钴蓝斜纹、琥珀；这是项目阶段局部映射。

## 4. 三种点阵必须分清

| 点阵 | 一点的含义 | 读数规则 |
| --- | --- | --- |
| 客户 KPI 单位阵列 | 1 条或明确标出的聚合单位 | 总数精确，末格可部分填充 |
| 客户集中度 10×10 圆点 | 约 1% 合同金额 | 按占比分配取整，以旁侧精确读数为准 |
| Growth 收入 wave canvas | 装饰性波纹，无金额或记录单位 | `aria-hidden`；金额由独立文本表达 |

Growth 装饰阵列的点数不是客户数或金额，不能给它附会单位。
不能因都用了点阵，就把 KPI 的计数规则套给集中度，或把装饰波纹当统计图。

## 5. 分母、口径、缺失与零

- 回款结构：`received / (received + pending)`；待收使用同一分母，不除以目标金额。
- 客户集中度：分组合同金额除以合同分布合计；保留与本期签约额口径不同的说明。
- 漏斗：当前阶段数量除以上一阶段数量；上一阶段为零时显示“—”。
- BD 比较条：金额除以本组最大金额；这不是个人目标完成率。
- 目标完成率：实际值除以真实目标；未设目标或分母为零时不造百分比。
- 超额目标可显示真实百分比；进度轨道封顶不应把文本读数也强行改成 100%。
- 缺失显示“—”或明确不可用；真实零显示 0，不能用零掩盖缺失。
- 零计数的阵列保持未点亮；零计数柱不绘制假柱；零金额不占虚构份额。
- 时间序列遇到缺失值断开，不插成零，也不让光带跨越无数据区间。
- 不合并不同币种、周期或统计快照；沿用原有汇率与缺失汇率提示。
- 百分比四舍五入后可能不恰好合计 100.0%；图形用原值，勿修改原数据凑数。

## 6. 配色、纹理与读数交互

- KPI 黑青面基准 `#152730`，可用 `#1b323c` 过渡及低强度内光；不加外光框。
- 数字默认 36px / 450；窄屏可降至 32px，说明允许换行，不能靠裁切塞满。
- 薄荷代表已收款/总量等当前约定；冰蓝代表待收/新增/交付等局部系列。
- 琥珀用于当前约定的延期或阶段；不同图表的同色不自动具有相同业务含义。
- 纹理是颜色之外的第二识别通道：待收冰蓝斜纹、延期琥珀斜纹、制作钴蓝斜纹。
- 阶段身份色保持稳定；选中用亮度、微抬升、状态文本表达，不洗成统一选中色。
- 点击比例块或分组按钮，联动精确读数与明细；再次点击可恢复全部（适用时）。
- 小比例块可省去块内文字，但必须保留旁侧图例、精确金额、占比及可访问名称。
- 集中度选中明细使用完整内嵌浅灰蓝卡，不让深色横条切穿白色分析面。
- 图形交互使用真实按钮与 `aria-pressed`；历史曲线支持键盘、触摸及日期读数。

## 7. 动效边界

- Customers 入场是有限动画：数字约 380ms，单位标记约 500ms，比例块约 950ms。
- 在视口内播放；切换数据后基于新数值呈现，不持续随机变动暗示业务实时增长。
- 选择反馈可以有一次轻抬升或扫光；数据比例在选中前后保持不变。
- 隐藏、卸载或 reduced-motion 时清理动画，静态状态仍显示最终准确读数。
- 不用统一 count-up 掩盖金额单位、负号、缺失值或 React 拥有的文本节点。
- Growth 现有装饰 wave / 历史交互属于保留的例外，不据此给所有 KPI 加无限循环。
- 装饰循环须与数据编码分离，离屏或页面隐藏时停下，reduced-motion 时静态呈现。

## 8. 已拒绝形式与源码边界

- 不恢复回款卡的“乐器状波浪管”：形态无法解释已收/待收关系；当前采用比例块。
- 保留 Growth 的重点 ROI 仪表盘，但不扩散到客户收款、计数和阶段构成。
- 不给单个累计值添加随机趋势、无单位的百分比环或假的目标进度。
- 不用大面积白卡承载密集客户/项目列表，不用突兀的深色条截断分析卡。
- 不加装饰性细线、无业务含义的闪烁、改变数据比例的透视效果。
- Customer 来源：`mobile/customers-src/customers.jsx` 的 `CXCollectionBlocks / FansaiCustomersBoard`。
- KPI 来源：`mobile/customers-src/kpi-cards.jsx` 的 `cxKpiUnits / CXKpiMatrix / CXKpiCountBars / CXKpiStages`。
- Growth 来源：`mobile/index.html` 解码后的 `gxGauge / gxRoiHistory / gxMountRoiMotion / gxMetricsMotion`。
- 当前 `gxMetricsMotion` 仅为收入渲染装饰 canvas；其他绘制函数尚存源码不代表已采用。
- 不将未挂载的 cost/download/reg/paid/cac 绘制函数、废弃试稿或被拒绝形态写成推荐库。
