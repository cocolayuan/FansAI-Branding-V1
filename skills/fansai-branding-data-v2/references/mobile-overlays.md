# 统一移动端浮层

客户筛选、时间/币种、客户详情、项目详情，以及目标页的账号菜单、资料、密码、语言和角色展示，复用当前 Growth 筛选的浅色底部 Sheet 家族。深色页面也用同一操作面。此处是移动端规则，不重写其他产品的桌面弹窗。

## 外壳

- 贴当前手机画幅底边，宽度 `min(100%, 480px)`，最大高度 `90dvh`；顶部圆角 `28px 28px 0 0`。
- 浅灰蓝背景 `linear-gradient(145deg, #F8FBFD, #EDF3F6)`；前景信息卡/普通选项是白色；页脚 `#F0F5F8`。
- 上方 24px、左右 20px、底部 `20px + safe-area`。≤350px 时左右收为 16px。隐藏旧通用拖拽条，避免混用另一套旧 Sheet 间距。
- 左上标题，右上中性文字“取消”或“关闭”。标题和退出一直可触达；长内容只让主体滚动，底部必要提交操作固定。
- 拆分头、主体、页脚时保持同一左右边线；页脚上内边距 16px。检查软键盘和内嵌下拉/日历不能被裁切。

## 行为与动作

- 有草稿的筛选/编辑：底部“应用筛选”“保存”等主操作占满可用主操作宽度；“重置”是轻量文字辅助。重置只改变草稿，提交后才改变生效值。
- 取消、Esc、遮罩退出不提交；重新打开从已生效状态初始化。不要为了统一外观删掉状态回调或把筛选改成立即生效。
- 只读客户/项目详情：右上“关闭”。不追加右下角孤立的深底薄荷“关闭”，不把退出误做主业务操作。
- 账号子层使用同一壳，保留原保存、验证、语言、权限和返回逻辑。已分配角色只展示已有授权，不增加角色分配入口。
- 原有“去审批”等真实动作按语义和权限保留；没有后端的新操作必须明确演示范围，不能显示假保存成功。
- 保留焦点进入、Tab 限制、Esc、关闭后焦点返回、背景滚动锁和安全区。详情关闭不需要无意义的确认。

入场约280ms、`cubic-bezier(.2,.8,.2,1)`，内部展开约160–180ms；减少动态时立即显示最终状态。检查本次变更实际影响的入口；若任务是统一 Customer 所有浮层，不能只改项目详情而遗漏客户详情、筛选或账号菜单。不扩大原任务范围。
